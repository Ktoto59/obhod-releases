# Обход для OpenWrt 0.1.5

Пакеты `obhod` и `luci-app-obhod` добавляют управление через **LuCI → Службы → Обход**.
Готовых туннелей, ключей и URL подписок в пакете нет. После установки служба выключена.

## Совместимость

- OpenWrt 24.10 с opkg: пакеты `.ipk`.
- OpenWrt 25.12 с apk: пакеты формата APK v3 `.apk`.
- Служба и LuCI не содержат машинного кода: один набор `all`/`noarch` подходит
  для Xiaomi AX3000T (MediaTek/Filogic) и Beeline SmartBox TURBO+ (MT7621).
- sing-box **1.12 или новее** устанавливается из репозитория вашей прошивки:
  `sing-box-tiny` для прокси или полный `sing-box` для WireGuard. Можно установить
  только интерфейс и выбрать протоколы позже в LuCI. Пакетный менеджер выбирает
  ядро и модули под архитектуру и ядро Linux роутера.
- Требуются firewall4/nftables, TUN и свободное место для sing-box. Поддержка
  не распространяется на заводскую прошивку роутера.

Проверки схемы конфигурации и браузерной логики не заменяют проверку на физическом
роутере. Первая версия требует проверки маршрута LAN, DNS и восстановления после
перезапуска на конкретной прошивке. Производительность на AX3000T и SmartBox TURBO+
ещё не измерена.

## Установка

Интерфейс разделён на пять вкладок: **Обзор**, **Подключения**, **Правила**,
**Протоколы**, **Сеть**. На обзоре отображается состояние и сводка. Во вкладке
подключений есть поиск серверов, выбор всех и сворачиваемый импорт. Правила
сгруппированы по регионам, сервисам, категориям и сетям; несовместимые наборы
отключаются сразу. Переключение вкладок сохраняет введённые данные.
Кнопки сохранения находятся в общей нижней панели. Оформление адаптируется
к светлой или тёмной теме LuCI и узкому экрану.

Онлайн-установщик (интерактивный выбор списков):

```sh
sh <(wget -O - https://raw.githubusercontent.com/Ktoto59/obhod-releases/main/openwrt/install.sh)
```

Переносимый вариант, если оболочка не поддерживает `<(...)`:

```sh
wget -O /tmp/obhod-install.sh https://raw.githubusercontent.com/Ktoto59/obhod-releases/main/openwrt/install.sh && sh /tmp/obhod-install.sh
```

Публичная копия скрипта содержит точную ссылку на комплект версии 0.1.5 и его
SHA-256. Перед распаковкой проверяется архив, затем все файлы внутри него.
Номер версии не запрашивается через `latest`, сертификаты HTTPS не отключаются.

Установщик показывает общий и доступный объём ОЗУ, накопитель `/overlay` (либо `/`)
и `/tmp`. ОЗУ не является жёстким условием установки: при малом объёме выводится
предупреждение. Устройство с 128 МБ или больше рекомендуется для работы, но
число подключений и списки могут существенно увеличить потребление памяти.

Для подготовки требуется 1 МБ в `/tmp` и 2 МБ на накопителе. После обновления
индексов рассчитываются недостающие зависимости по APK query/opkg dry-run.
Когда нужны крупные зависимости (8 МБ или больше без сжатия), требуется минимум
15 МБ свободного flash, как начальная проверка в установщике Podkop.
Размер после распаковки показывается как оценка: он не равен фактическому месту
на сжатой flash. Если оценка выше свободного места, установка разрешается с
предупреждением. Окончательный контроль места выполняет apk/opkg штатными
средствами; принудительное игнорирование нехватки места не используется.
На накопителе с 30–40 МБ свободного места может поместиться tiny, но это зависит
от архитектуры, версии ядра, файловой системы и уже установленных зависимостей.
Успешная установка не гарантирует достаточную ОЗУ для работы под нагрузкой.

Первое меню выбирает протоколы: прокси (VLESS/Reality, Shadowsocks, Trojan,
Hysteria2, TUIC, AnyTLS, SOCKS/HTTP), WireGuard, все поддерживаемые либо выбор
позже в LuCI без установки ядра. Протоколы скомпилированы в общее ядро:
выбор одного VLESS не удаляет остальные функции из `sing-box-tiny`.
При автоматическом выборе на устройствах с менее чем 192 МБ ОЗУ используется
облегчённое ядро; уже установленное ядро сохраняется. Принудительная смена
варианта установленного ядра выполняется в LuCI после выключения Обхода.
Обязательная зависимость от `curl` удалена: подписки загружаются штатным
`uclient-fetch` с проверкой HTTPS, таймаутом и ограничением 128 КБ.

Следующее меню предлагает рекомендуемые списки, минимальный набор, выбор по номерам или
установку без готовых списков. Рекомендуемый набор: `russia_inside`, `discord`,
`meta`, `telegram`, `google_ai`. Несовместимые региональные наборы не допускаются.
Для облегчённой установки и установки без ядра по умолчанию выбирается минимальный
набор: Discord, Telegram, Google AI. Выбор сохраняется в `/etc/obhod/defaults.json`
и появляется в LuCI после установки.
Существующий профиль с подключениями и списками не перезаписывается.

Для автоматизации и диагностики:

```sh
sh /tmp/obhod-install.sh --yes --check-only
sh /tmp/obhod-install.sh --yes
sh /tmp/obhod-install.sh --yes --protocols proxy --presets minimal
sh /tmp/obhod-install.sh --yes --protocols none --presets none
sh /tmp/obhod-install.sh --protocols all --presets discord,telegram,youtube
```

`--check-only` не устанавливает пакеты и не записывает настройки; индексы
пакетного менеджера обновляются в `/tmp`. Недостаток минимального места или
неизвестные размеры зависимостей останавливают установку. Эта предварительная
проверка не заменяет окончательную проверку пакетного менеджера.

## Выбор протоколов после установки

### Обновление самого Обхода

На вкладке **Обзор → Обновления Обхода** нажмите **Проверить обновления**,
затем **Обновить Обход**. Сначала сохраните изменения на странице: установка
не запускается, пока есть несохранённые данные. Проверка и установка работают
в фоне, поэтому страницу можно закрыть. После завершения нажмите
**Открыть новую версию**.

Обновляются пакеты `obhod` и `luci-app-obhod`; выбор ядра остаётся во вкладке
«Протоколы». Версия читается из фиксированного публичного репозитория проекта,
архив проверяется по SHA-256 до распаковки и установки. Сохранённые подключения
и списки сохраняются. Если Обход был включён, на время установки он остановится
и будет запущен снова. При ошибке установки профиль сохраняется; пакетный
менеджер может потребовать повторную стандартную установку.

Для перехода с версии 0.1.4 и более ранних версий потребуется один раз выполнить
обычную команду установки. Начиная с 0.1.5 обновления доступны через LuCI.

### Установка ядра

Откройте **LuCI → Службы → Обход → Протоколы**. Выключите Обход, выберите набор
и нажмите **Установить выбранные протоколы**. Проверка памяти и установка идут
в фоне, состояние обновляется на странице. Используются штатные подписанные
репозитории, формат apk/opkg определяется автоматически. Подключения не изменяются.
После завершения нажмите **Сохранить и включить**.

APK заменяет ядро одной транзакцией. Для opkg до удаления прежнего ядра
загружаются оба пакета и сверяются SHA-256 из подписанного индекса; при ошибке
установки выполняется попытка восстановления прежнего ядра. Если другой пакет
требует старое ядро, принудительное удаление не выполняется. Перед переходом
на tiny нужно удалить из профиля WireGuard и сохранить изменения.
Выбор WireGuard устанавливает полный sing-box, поэтому прокси также остаются
доступны. Списки и число одновременно проверяемых серверов влияют на ОЗУ при работе;
на устройстве с 128 МБ начните с минимальных списков и небольшой группы.

Можно также установить комплект без загрузки через скрипт:

Скопируйте архив `obhod-openwrt-0.1.5.tar.gz` на роутер в `/tmp` и выполните:

```sh
mkdir -p /tmp/obhod-install
tar -xzf /tmp/obhod-openwrt-0.1.5.tar.gz -C /tmp/obhod-install
sh /tmp/obhod-install/install.sh
```

Установщик проверяет OpenWrt, контрольные суммы комплекта и наличие пакетного
менеджера. Если доступен настроенный apk, использует `.apk`; иначе opkg и `.ipk`.
Зависимости устанавливаются с обычной проверкой подписей репозитория. Локальные
пакеты этой сборки не подписаны; `--allow-untrusted` применяется только к ним с
`--no-network`. Постоянные настройки доверия и репозитории не изменяются.

После установки перезагрузите страницу LuCI: для регистрации API и прав доступа
rpcd перечитывает конфигурацию с сохранением сессий. При изменении прав может
потребоваться повторный вход. Импортируйте URL V2Ray-подписки, список
ссылок/Base64, одну ссылку или текст WireGuard `.conf`. Поддерживаются VLESS/Reality,
Shadowsocks, Trojan, Hysteria2, TUIC, AnyTLS, SOCKS5, HTTP(S) и WireGuard при наличии
соответствующих возможностей в sing-box. AmneziaWG и VMess пока не поддерживаются.

Выберите основной сервер либо минимум два сервера для автоматической группы.
Добавьте сайты, подсети или готовые наборы. Укажите LAN-устройство Linux
(обычно `br-lan`), затем нажмите **Сохранить и включить**. Имена WAN-устройств
добавлять не нужно. URL подписки используется однократно и не сохраняется;
для получения новых серверов повторите импорт.
Размер загружаемой подписки на роутере ограничен 128 КБ; локальный профиль — 192 КБ.
Ограничения учитывают размер сообщений RPC и память роутера; при превышении
профиль не записывается и действующие настройки сохраняются.

## DNS и остановка

При автоматическом управлении DNS сначала сохраняются upstream-серверы и
`noresolv` одного экземпляра dnsmasq в `/etc/obhod/dns-backup.json`. После запуска
DNS-слушателя dnsmasq направляет внешние запросы на `127.0.0.1#1053`. Локальные
имена и DHCP остаются у dnsmasq. При остановке или завершении процесса прежние
настройки возвращаются. Если настройки DNS изменены другой программой, Обход
оставляет резервную копию и не перезаписывает чужие изменения.

Для нескольких экземпляров dnsmasq используйте ручной режим DNS и настройте
нужные экземпляры на upstream `127.0.0.1#1053`. Другие менеджеры прозрачного
прокси нужно остановить до запуска Обхода. Правила приложений Windows на роутере
не используются; текстовые внешние списки `.txt`/`.lst` пока не поддерживаются.

```sh
/etc/init.d/obhod stop
/usr/libexec/obhod/dns restore
logread -e obhod
```

Настройки и ключи хранятся в `/etc/obhod/settings.json`, доступ только root
(каталог 0700, файл 0600). DPAPI Windows на роутере отсутствует: защищайте SSH,
LuCI и резервные копии прошивки. Пакеты не включают удалённый доступ и не открывают
API управления на WAN. При остановке ядра системного kill switch нет.

## Сборка

Исходники пакетов: `openwrt/obhod` и `openwrt/luci-app-obhod`. Парсеры подключений
и генератор общие с Windows-версией; браузерный модуль собирается из исходников:

```sh
node scripts/build-openwrt-core.js
python3 scripts/build-openwrt-packages.py --apk /path/to/apk --output release/openwrt
```

Проверки разработки:

```sh
npm test
npm run test:openwrt:ui
npm run openwrt:fixture
python3 scripts/test-openwrt-system.py
npm run test:openwrt:ui -- --luci-loader .tmp/openwrt-tools/luci-25.12.6.js --luci-theme .tmp/openwrt-tools/luci-bootstrap-25.12.6.css
```

Команда `python3 scripts/test-openwrt-system.py` запускается от root в отдельной Linux-среде. Она создаёт
тестовый rootfs в `/tmp/obhod-openwrt-lab`, проверяет установку APK и IPK настоящими
пакетными менеджерами, транзакции UCI/DNS и откат RPC. Для проверки установки
зависимости заменяются тестовым пакетом; службы и сеть физического роутера не
затрагиваются. Для проверки ошибок запуска используется управляемая заглушка ядра.
Полная схема конфигурации отдельно проверяется настоящим Linux sing-box 1.12.22.
Системная проверка также извлекает штатный `luci.js` из проверенного образа в
`.tmp/openwrt-tools/luci-25.12.6.js`. Последняя команда использует именно его
загрузчик классов: воспроизводит ошибку обычного object-экспорта и проверяет
загрузку исправленного модуля, наследующего `baseclass`, перед проверками UI.
Также используются штатный DOM LuCI и стили Bootstrap: проверяются значения
чекбоксов, вкладки, сохранение ввода, несовместимые списки и ширины 320/390 пикселей.
Изображения тёмного, светлого и мобильного интерфейса сохраняются в `.tmp/openwrt-ui-preview`.
Код LuCI используется только в тесте и не включается в наши пакеты.

Для создания APK нужен Linux и apk-tools 3 с командой `mkpkg`. Для этой сборки
использован официальный `apk-tools-static 3.0.8-r0` Alpine Linux; инструмент
сборки и sing-box в распространяемый комплект не включаются. SHA-256 архива
инструмента: `673f1bfb22136fc42ca035321cf731a4ad0452c000928666cb39a138f0c277bf`.
Пакеты можно также включить в SDK с установленным feed LuCI; Makefile находятся
рядом с исходниками. Собственный код распространяется по Apache-2.0.

Документация первоисточников: [TUN/auto_redirect sing-box](https://sing-box.sagernet.org/configuration/inbound/tun/),
[APK mkpkg](https://gitlab.alpinelinux.org/alpine/apk-tools/-/blob/v3.0.8/doc/apk-mkpkg.8.scd),
[пакет sing-box OpenWrt 24.10](https://github.com/openwrt/packages/blob/openwrt-24.10/net/sing-box/Makefile).
